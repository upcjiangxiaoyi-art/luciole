## v3.5.1 热修：案件模式编译当场崩（2026-08-21）

**症状**：案件模式点编译 → `undefined is not an object (evaluating 'caughtVerdict.answer')`，重试两次后整个编译失败。

**原因是我的低级错误**：`var caughtVerdict = blankVerdict();` 被写在了 `return Promise...` **之后**。函数声明会提升所以 `callBatchWithRetry` 能正常定义，但 `var` 只提升声明、不提升赋值——那行赋值永远执行不到，运行时 `caughtVerdict` 是 `undefined`，一读 `.answer` 就炸。赋值已挪到 `return` 之前与其它状态变量并列。

**更该记的是为什么没测出来。** v3.5.0 的测试全是把 `parseCluesJson`、`revealText` 单独抠出来验的——**从没跑过编译主流程**，所以这种作用域/可达性的错完全在盲区里。

新增 `t-flow.js`：把整个 `compileStory` 拿出来跑，只把 API、DOM、账本换成假的。验证谜底落盘、只取第一批、秘密模式不写 verdict、模型没给谜底时不崩。

**并且拿 v3.5.0 的代码反向验过这个测试**——它确实抛出了一模一样的 `caughtVerdict.answer`，证明这个测试真能抓到，不是摆设。


## v3.5.0 案子有答案了（2026-08-21）

### 这局案子原本是无解的

隐藏脉络里写「镜湖浮尸案，编译 ai 自己给线索和最后的凶手」——**谜底是编译时现编的，但从来没被记下来过**。它心里定了个人、照着编了二十条证据，然后就忘了。线索存下来了，答案没有。玩到最后没人知道谁干的，连揭底都没东西可揭。

现在补上闭环：

**编译时产出并存下谜底。** 案件模式的输出契约从 `{"clues":[...]}` 扩成三个字段：

- `clues` —— 证据，照旧
- `answer` —— **完整谜底**，给玩家复盘看：谁做的、怎么做的、为什么、哪几条证据指向他、哪几条是误导以及为什么会被误读
- `oneline` —— **一句话揭晓**，40 字以内，给演员当场说破用，只说结论不解释推理

提示词里写死了一条：底牌若没指名道姓，**必须自己定一个说得通的答案并完整写进 answer**——证据是照着答案编的，答案没写下来这局就永远无解。

谜底只在第一批收（那一批的上下文最全），存进账本。**揭底之前它不出现在任何注入里**——已逐个函数核对：`injectText` / `actInjectText` / `briefInject` / 三个 UserPrompt 全部为零引用，只有 `revealText` 会读它。

### 揭底：一句话给演员，整份给你

**给演员的是 `oneline`，不是整份谜底。** 整份塞过去它会照着念推理过程，戏就没了。注入同时要求它「接着当前这场戏往下演，让在场的人各自有反应」——这样揭晓是串进剧情的，不是插播一段公告。

**给你的是 `answer`**，揭底后在复盘卡片顶部摊开，配着下面那张线索清单看：哪一条当时指向哪儿、哪一条是误导。

没存下谜底时（旧账本 / 编译没给），揭底会先弹窗说明，同意后回退成把底牌原文交给演员，不阻塞。

## v3.4.0 案件玩法 · 揭底 · 「不准」泄密修复（2026-08-21）

### 三幕各管一种玩法，一个玩法只开一幕

用插件的人不会为了一桩案子把三幕全配一遍。分界线不是「是不是探案」，是**掉落的东西是信息还是场景**：

- **被动察觉**（玩家在过日子，身边的事越来越对不上）→ 收到的是**信息** → 帷幕沙漏
- **主动调查**（去现场、去档案室，走到哪儿照亮哪儿）→ 收到的是**场景** → 迷雾森林

所以**小案子归帷幕沙漏，现在就能玩**；要跑很多地方的大案子（剧本杀 / 无限流 / 穿越）等迷雾森林。

### ① 故事区新增玩法二选一

**🕯 藏一个秘密** / **🔍 查一桩案子**。切换时底牌的标签与示例跟着变。

两套编译提示词分开，因为**它们的要求是直接打架的**：

| | 秘密 | 案件 |
|---|---|---|
| 载体 | **不重复**（二十个不同角度） | **要复现**（同一个编号出现在两条以上，玩家才拼得起来） |
| 递进轴 | 越来越难解释得通 | 可查范围逐渐收窄 |
| 假线索 | 不需要 | 真实存在但容易被误读的证据，**不能是凭空捏造的假货** |

一套提示词凑不出来。⑤提示词抽屉相应多一格「编译提示词 · 查一桩案子」，可自行修改。

### 🎴 揭底

前面所有动作都在藏，这一个是反的：**把底牌一次性交给演员**，从下一次回复起正面揭晓。点亮或完结状态下都可揭，揭过即锁；「重置进度」会连揭底状态一起收回（否则重开一局开局就是明牌）。

揭底时日志给出复盘数据：这一局送出过几条、还剩几条没用上。

### 「不准」正在泄密 —— 已修

v3.3.0 的第二幕把「不准」原样注给演员，规格书举的例子是「不准男主发现孩子是他的」。**你要拦一件事就得先说出这件事，说出来它就进上下文了**——模型第一件知道的就是有个孩子、是他的。而这个秘密可能第一幕正藏着，两幕互相拆台。何况模型对否定句处理本来就弱，说「不准 X」反而让 X 更显眼。

三处一起修：
1. **切星提示词加铁律**：「不准」只写行为不写事实，并给出反例（不准男主发现孩子是他的）与正例（这一段两人不能把话说破）
2. **注入措辞**从「本段不会发生」改为「本段的边界（演到这里为止，不要越过）」——划线而不是陈述世界
3. **机器闸**：「不准」与第一幕秘密做 6 字连续重合扫描。手动编辑时拦下并提示；切星产出时只摘掉那一栏、不废整幕，日志说明。两幕各写各的账本，这道闸让它们对上话

*顺带修正：小萤火那一格的说明文字还停在旧版（写着「弃 编号」，该功能 v3.2.0 已删）。*


## v3.3.0 星星点灯 · 剧本在小萤火手里，演员手里只有这一页（2026-08-21）

**三个模式是同一件事的三种下放：哈基米不能拿全量信息，小萤火坐在外面管着给。**帷幕沙漏管一个秘密，碎成线索往下漏；星星点灯管一条脉络，切成幕往下放；迷雾森林管一个场景库，一幕一幕下放。三者完全独立。

### 星星点灯：在 v3.0 分镜骨架上加三块

骨架没动（一次只挂一幕／只进不退／换幕留痕／降温语）。加的是：

- **✨ 扔大纲 → 切成星。**随便写一段「我想玩带球跑……」，小萤火（编译连接）切成 3～12 幕，每幕三样：**演什么**／**到位**（演到什么算完）／**不准**（这一段绝对不能发生的事）。伏笔不单独给演员，折成当前幕里一两个不动声色的小动作。切出来的能改能删能调序，也能继续手写追加。
- **演员只看当前这颗星。**注入只有「演什么」+「不准」+ 降温语。**「到位」不注入**——它是给你看进度的，给演员看等于告诉它该翻页了。前后幕连影子都不给。
- **轮钟翻页。**全局默认每幕几轮（你自己填），每幕可单独覆盖（开演后也能改，临场调节奏是常态）。演满自动翻下一幕；最后一幕演满进**落幕态**——幕本仍挂着，撤了演员会掉回角色卡的全量态。翻早了「撤回上一幕」，翻晚了「推进下一幕」。
- **🔀 从这里接上。**你自己拐了弯（剧情走到大纲外面去了）——点一下，小萤火读现场 + 原大纲，**只重切当前幕之后的**，当前幕不动。演员自己拐弯是另一回事，靠每幕的「不准」拦，跟这个按钮无关。
- **🌠 星图**默认折叠：每幕一行、✓ ✦ ·、轮次区间从流水里推。进度，不是剧本。
- **没有领航员。**每轮 API 判到位那条路不走了——省钱、可控、不会有「它判错了我还不知道」。字段也没留。

**迁移：**v3.0 手写的幕本自动升到 v3，「进场条件」并入上一幕的「到位」，其余字段补默认，流水里留一条提醒你补「不准」。v2.8 的愿望星图仍不迁移。

### 帷幕沙漏：🐾 习性单（抢话悖论的解）

悖论：模型要替你演 user，不知道 user 是狐狸就 OOC；知道了三把就漏。

解法：**秘密拆两层。**底牌（为什么）归沙漏管；**习性单（她怎么活着）第一轮就给演员**——说话方式／说话语气／身上的习惯，每栏三到五条，只写「怎么样」不写「为什么」。行为是真相长出来的：演员不知道真相也能演出真相的影子，而那个「她自己也说不清」的怪，本身就是伏笔。

- 在 ① 故事里写好隐藏脉络，点「🐾 生成习性单」→ 三栏可编辑 → 「📋 复制全部」粘进你的角色栏。**插件只管生成，不注入。**
- 末尾写死一句留白：「这个人身上有些地方她自己也说不清，遇到的时候顺着演就好，不要往合理了圆。」——给演员的许可：碰到没覆盖的地方敢往怪了演。哈基米的毛病就是把不合理圆成合理，一圆秘密就漏。
- 安检三层：生成后同一连接再当一次**审查员**（删带原因、能反推底牌的条）→ 本地 **8 字滑窗**与底牌比对（比线索的 12 字严，因为这东西要进角色栏，暴露面 100%）→ 禁词表。审查员没回应不致命，本地两层还在。
- 随身须知（第二幕 ④）保留为逃生口，说明改为「习性单优先」。

### 提示词抽屉

新增两格：**切星**／**习性单**。审查员提示词与留白句写死在代码里，不进编辑区——它们是安检的一部分，不是腔调。

### 顺手

- `boot()` 里残留一句对已删函数 `starClearInjection()` 的调用，3.0～3.2 开机会在这里抛错（面板已挂好、事件已绑，但开机的那次现场还原和守卫自检没跑）。删掉了。
- 面板顶部的第二幕副标题仍是「分镜成长」，没改——名字是你的。

## v3.2.0 God 编命运，小萤火扔牌（2026-08-15）

**分工立起来了。** 之前所有别扭都来自同一个错误：我们让小萤火去理解剧情（那是 God 的活），让 God 去管场合（那是小萤火的活）。两边都在干对方的事，谁都干不好。

### 小萤火：只对场合

它的工作被砍到最简——**看一眼现在这场戏在什么场合，从清单里挑一条此刻演得出来的，回一个序号。**

- **不再读十层剧情**，只给 5 层（够知道"在哪、在干嘛"）
- **不再切 5 条候选窗口，全池摊开**。限制候选反而可能让当下场合的那张牌根本不在桌上
- **必须给完整原文**，不能给标签：同样在医院，胃病和孕检完全两回事，标签区分不了
- **编号从随机串改成序号 1…N**。抄不错的数字，不会再有「看不懂」
- **删掉弃牌任务**。那是压垮它的额外负担之一——它只需要指一下，不理解、不改写、不加工

### 编译：三条硬规矩，其余降为默认

原先提示词里那些"线索该长什么形状"的规定是越界的。现在只留三条机制约束——**别说破、能独立演、别绑死当前场景**——其余全部降为默认写法，用户可在⑤提示词里改。

默认写法按实测反馈重写：
- **长在这个故事里**：用角色卡与世界书里真实存在的人、地点、物件、职业、习惯、关系做载体
- **铺得开 + 合理延伸**：覆盖这个角色一生可能走到的各种场合。人在北京，那出差、旅游、回老家、机场、外地医院都算合理；不合理的是与这个人八竿子打不着的东西
- **有脉络**：整批像同一件事慢慢浮出水面，不是一堆互不相干的怪事
- 载体轮换、内容与载体分离、40～90 字

### 注入：从「任务」改成「在场的事实」

「舞台指示」把线索定位成一条给演员的**额外任务**——忙不过来时当然先扔掉。现在改成告诉模型**这个世界现在是这样**：

```
【本回合场景中已存在】
（线索原文）

它就在那里。用当下场景里自然的方式让它出现——上面若举了例子而此刻不合适，换一种做法。
不要为了它把场景拉回别处；此刻若确实用不上，它就只是背景。不要提及这段文字本身。
```

去掉了「自然融入演出即可」和「不要向玩家解释」——这两句都是在给模型退路。

**「不合适就是背景」这句是设计的一部分**：正因为不合时宜的牌只会变成背景而不会变成错误，零 API 的顺序档和随机档才照样能跑。三种模式不是好中差，是三种代价不同的选择——零 API 的代价是偶尔不贴，小萤火的代价是每轮多一次调用。


## v3.1.0 第一幕职能理顺（2026-08-15）

### 病房打转：这是 bug，不是提示词没写好

编译时代码抓最近 40 条正文，然后给**每一批**都附上一句「线索必须衔接以上现场：沿用已出现的人物、地点与正在进行的情节」。在病房里编译，二十条就全被要求沿用病房——模型照做了，是我们下的指令错了。

**这句话对第 1 条是对的，对第 20 条是灾难**：第 20 条可能一百轮后才投放，那时人早出病房了。绑死的迹象要么演不出来（看起来像「AI 不执行」），要么硬把场景拽回去（看起来像「打转」）。

现在正文只用于两件事：了解世界与已发生的事实（别写矛盾）、知道玩家已经注意到什么（别重复）。**明确禁止据此锁定场景。**

### 第一幕的形状改了：从「案件链」到「一个事实的多角度渗出」

原提示词第一句是「把**通往真相的路**拆成一串按顺序投放的线索」——那是案件链：A 推出 B，B 推出 C，缺一环就断。

但第一幕实际服务的是**静态事实**：她不是亲生的／某组织其实是反派／她怀着他的孩子。这些没有「路」，只有**从二十个不同角度反复渗出来**。这个错配是「线索稀碎」的另一半原因——我们让它写链条，它在写同一件事的碎片，两边对不上。

新的写法：
- **每条独立成立**，不依赖前一条（因为它们会被打乱、跳过、延后几十轮）
- **递进轴改为「越来越难解释得通」**——第一条随口能带过，最后一条圆不回来。不是时间顺序，也不是因果链
- **载体必须轮换**：物品／口误／生理反应／习惯／文件／旁人的反应／梦／气味，同一种不用第二次
- **内容与载体分离**：先写清「要让人察觉到什么」，再给「可以怎么带出来的例子」——例子只是例子，演员可换成当下自然的做法
- 每条 40～90 字（原 30～80，分离内容与载体后需要更多篇幅）

顺带：事实型的迹象天然可以打乱，v2.9.0 的分层洗牌歪打正着，正好适合这种形状。

注入模板加了一句：**「不要为了执行它把场景拉回去」**——直接治打转。God 提示词按同一形状对齐。

### 诊断

- 调度员三层兜底都没认出来时，**把它的原话前 80 字打进日志**。「看不懂」三个字查不下去，得知道它到底说了什么。God 的设计被安检拦下时同理。

## v3.0.0 分镜成长（2026-08-15）

### 第二幕重做：许愿领航 → 分镜成长

**为什么换。** 许愿模式的爆点是「盲档 + 复盘」——玩八十轮之后才发现那场雨是自己许的愿。但角色卡通常只玩一周，用户不可能忘记自己想玩追妻火葬场，惊喜降成了确认。为一个确认感建铁律 1、翻译层、6 字指纹扫描，不值。整套连同盲档一起撤下。

**新的做什么。** 用户把角色的一生切成几段幕本，小萤火按顺序挂上去。角色卡是一整块塞给模型的、没有时间轴——写着「18-27 开朗、30 后心狠手辣」，模型读到的是一个全部特质同时在线的人，开局第一句就带狠劲。分镜一次只挂一段，**后面几段根本不在它的上下文里，所以它演不出来**。不是压着不演，是真的不知道——比任何「请循序渐进」的指令都硬。顺带也把「这一段我想玩追妻火葬场」这类段落基调一起带进去，比挂在预设里省，也比挂在预设里准（预设是「一直有」，分镜是「到时候才有」）。

**每一幕装三样**：幕名 / 进场条件（小萤火据此判断该不该进）/ 这一段怎么演 + 想要什么戏。

**四条规矩**：
1. 同一时刻只有一幕挂着——换幕即覆盖，旧的必须真的消失，不消失梯度当场塌
2. 只准前进不准后退——AI 判断一定会错，后退只能由人手动，专门给了「撤回上一幕」
3. 换幕必须留痕——哪一轮、从哪到哪、为什么
4. 注入末尾强制附一句降温语，不进用户可编辑区：模型刚拿到明确的戏剧目标天然想当场兑现，不压住第一句就让男主跪下

*本版先出结构与面板，领航员 API 尚未接入——目前由「推进下一幕」手动推。*

### 随身须知（第三条注入通道）

写模型该知道、但绝不能说破的事（user 其实是狐狸、顶替了谁）。平时不在上下文里，**按一下才进，管完即撤**。适合 Gemini 要替你演 user 的那一轮——那也正是你信息最全的时刻（写完消息、发送之前）。

注入位在 depth 1，比角色卡（在最顶上、可能三万 token 之外）注意力高得多：**平时没有，要用的时候贴脸**。

提供 `/lc-brief` 与 `/lc-brief-off` 两个命令可绑 Quick Reply，面板上也有等效按钮兜底。

⚠ 诚实说明：这是拿「物理隔离」换「演绎精准」。须知进上下文的那一轮，模型写出来的正文会永久留在楼里——注入能清，正文清不掉。所以须知模板里强制带禁令与降温语，把那一轮能写的东西框住。暴露面从 100%（写进角色卡）降到按需的几轮，是量的改善，不是质的解决。

### 三幕分家

- **切页**：顶部三个 tab 真正切页，不再是滚到底部的抽屉。当前页记进设置，换聊天回来还在原处。切页用显示/隐藏，绝不重建 DOM——重建会踩掉输入框焦点。
- **日志分家**：第一幕「帷幕日志」、第二幕「星灯日志」各记各的。不属于任何一幕的系统消息（守卫自检、版本）两边各写一条。
- **API 分家**：小请求管道降为公共的 `callSmallApi(配置名, …)`，不再挂在第一幕名下——第一幕整个搬走时第二幕不会跟着断。星灯的连接槽 `api3` 已留出，三项留空即复用编译连接（与调度员同一套规矩）。
- **三条注入通道**：线索（一次性）／幕本（常驻）／须知（一次性手动），各走各的 key，绝不合并——合并的话正挂着幕本时按一下须知就会把幕本冲掉。


## v2.9.0 五项排雷（2026-08-15）

**① 编译覆盖必须确认。** 原先点「编译」是无提示直接覆盖的——已送出 7 条的故事手滑一点，线索连同进度一起没。现在会明确告知会覆盖多少条、其中多少条已送出，并提示「想保留就点追加」。

**② 追加线索。** 新增「＋ 追加」抽屉：现有线索与进度一条不动，只往池子末尾补新的。**正点亮着也能追加**——玩到一半想补货是常态，不该逼人先熄灭。喂给编译器的上下文按「玩家已经见过的」和「已备好但还没投的」分开报，两者对模型意义不同，混一起它就分不清了。另有「本次追加的额外要求」自由输入框，深度与方向由你写，代码不替你决定。追加与重编各用一个草稿槽，互不串。

**③ 发牌顺序三档。**
- 按编译顺序（浅→深，原行为）
- **分层洗牌**：池子切前/中/后三段，段内随机、段间保序——有意外感，又保住「越来越接近真相」
- 纯随机（盲撒）：会打掉浅→深的设计，建议配一套「同层线索」的编译提示词预设

**顺序在点亮时摇一次并落盘**，本局不再变。绝不每次现摇——重抽、回拨都会让顺序漂移，那种 bug 极难查。追加的新牌接到序尾（随机档在这批内部洗一次），不重排老牌。

**④ 改间隔立刻生效。** 原先 `next_due` 在线索上台那一刻就算死了，中途改间隔要等下一条送完才生效，体感是「我改了怎么没反应」。现在按 `上次上台轮 + 新间隔` 重算，**但至少还要再等一条消息**——缩短会立刻变快，拉长会立刻变慢，且永远不会一改就当场炸出一条。

**⑤ 调度员三层兜底识别。** 便宜快模型常常「内容选对了、格式不对」——随机编号对它没有意义还容易抄错，于是本能地改成复述内容，我们搜不到编号就整份扔掉。现在编号搜不到时依次认序号（第2条 / 3. / ② / 选 1）和线索原文开头十字指纹。三层都取位置最靠前者，避免它先复述一堆再给答案时选错；完全无关的回话仍然返回空，不硬认。

**⑥ 线索调序。** 作者模式下每条线索加 ↑↓。已送出的不参与调序（已经在故事里了，挪位置没意义还会误导）。


## 这一版是什么

把 v1.6.x 的 9054 行推翻重写为约 2100 行（三模式全含）。只保留一个承诺，并把它做到可靠：

## v2.7.0 提示词开口（2026-08-14）

面板新增 **⑤ 提示词** 抽屉（平时关着，不改也能用）。四格可编辑：编译 / 调度员 / God / 注入模板。

**可编辑的和代码接管的是分开的。** 「怎么写」——铁律、语气、举例、力度——归你；「怎么交货」——`{"clues":[...]}` 的形状、调度员「第一行只输出编号」、God「暂缓输出 HOLD」——由代码永远追加，不进编辑框。这三条是解析器的依赖，被误删会静默失败，而报错长得像模型抽风，极难查。抽屉里会灰字告诉你每一格代码接管了什么。

**占位符**：编译格与 God 格可用 `{{力度}}` `{{禁词}}`；注入模板必须含 `{{线索}}`——缺了会被拒绝保存，因为那是唯一进演员上下文的内容，缺了故事照跑但一条线索都送不出去。删掉 `{{力度}}` 只提示不拦（你可能就是想写死）。

**预设**：存全局，与聊天无关。`内置` 是保留名，永远等于代码默认值，改不动删不掉——随时有个干净的参照可比对。想改就「新建副本」。每格有独立「还原」，改过的格子标一个点。

**小口子**：每个故事可勾「本故事固定用这套」，不勾则跟随全局当前选择。故事锁定的预设被删除时自动回落到内置，不会因此跑不动。

⚠ 换预设只影响**之后**的编译与 God 裁决。已经编译好的线索不会变——想让新腔调生效，需要重新编译。

## v2.6.3 圆回来了（2026-08-14）

停在避风塘里的萤火在白色主题下显示成方块。根因不是裁切，是渐变写法：`radial-gradient(circle, ...)` 不指定尺寸时按**最远的角**算半径，颜色到边缘中点还没褪干净，四角反而是满的——只要圆角被别的插件用 `!important` 盖掉，方形就露出来。以前是暗琥珀色、在深色主题上看不出来，换成亮黄绿压在白底上就全露了。

- 所有渐变改用 `closest-side`：颜色在最近的边就褪成透明，**四角真正是空的**，圆不圆从此与 `border-radius` 无关，谁也盖不掉。
- 萤火本体**不再用 `box-shadow` 发光**——阴影跟着圆角走，圆角被改方光晕就是方的。外晕整个搬到容器的圆形渐变上。
- 萤火盒子 18px → 26px：`closest-side` 的半径是边长的一半（13px），刚好等于旧版按最远角算出的半径（12.7px），换算法之后视觉大小不变。
- 停泊态的样式不再只认 `#extensionHarborDock` 这个 id，同时认避风塘设在浮标上的 `data-harbor-parked` 属性——避风塘将来改容器名也不会失效。

- **编译中断保护**：编译期间切聊天不再静默丢结果，会明确报「本次作废」，草稿仍留在原聊天可续跑。
- **改线索不再被推平**：作者模式下正在改某条线索时，AI 回复/重抽不会再重建列表抹掉你的输入；失焦后自动补渲染。
- **调度失败不再被重抽反复触发**：一轮里调度员/God 出错后记为「本轮已试过」，下一轮再问，不会每重抽一次就重打一次接口。
- **结束语更诚实**：被剧情越过而废弃的线索不再被算作「已送完」，日志分开报送出数与废弃数。

## AI 监督（v2.2.0）

「真相先锁，God 现场设计这一程光。」

- **无需编译**：写好隐藏脉络直接点亮
- 每到间隔轮，God（调度员/God 连接位，建议强模型）在两轮空档里读近期剧情 + 完整秘密，裁决：**HOLD 暂缓**（下一轮再问）或**现场设计一条 30~80 字舞台指示**
- God 有创作权，但**没有免检权**：设计稿必须过全部本地安检（禁词 / 宏 / 与秘密原文 12 字连续重合），拦下按暂缓处理并记日志
- God 设计的指示进入账本走完整簿记（上台 / 重抽复用 / 退役 / 现场还原），与编译线索一视同仁
- 连续暂缓 ≥3 轮会在日志提醒你检查秘密写法或调高力度
- 超时 / 出错 = 本轮不投、下一轮再问，故事永不被锁死

## 连接小贴士

- 编译连接与调度员/God 连接都有「拉取模型」按钮：GET /v1/models 后点模型名输入框即可下拉选择，也支持手动输入（中转站友好）

## 智能调度（v2.1.0）

一轮流水线设计：AI 回复落地后、你阅读打字的空档里，调度员（可配便宜快模型）读最近剧情，从未用候选的头 5 条里选最贴现场的一张；你下一条消息发出的瞬间，选好的牌**同步**注入——注入时序与均匀模式完全相同，物理安全。

- 调度员只有选牌权，没有创作权，也读不到完整秘密
- 解析不依赖 JSON：直接在回话里搜候选编号（随机串，零误匹配）
- 超时 / 胡话 / 预选失效 → 确定性回退为按顺序发牌，日志明说，**永不 hold 死故事**
- 调度员连接独立配置（④连接底部），三项留空即复用编译连接


## ✨ 星星点灯（第二幕 · v2.8.0）

「把星星交给我吧。愿望不说破，路自己会弯。」

把愿望折成星星：**亮星**是想去的方向（"我想经历一场双向暗恋"），**暗星**是禁区（"不要车祸失忆"）。锁定后，小萤火每隔 N 轮（≥5）在你读回复的空档里抬头看一次星图，三选一裁决：**空转**（顺其自然，合法且常见）／**矫正**（撞暗星或严重偏航时把故事轻轻拽回）／**点星**（把一颗亮星翻译成"世界里发生的事"推进剧情）。

四条铁律，全部本地执法：
1. **星语不落地**——愿望原文只进领航员的眼睛，事件正文与愿望有 6 字连续重合即被安检拦下
2. **弯路不弯真相**——星通道与线索通道完全独立，无权碰秘密与线索账本
3. **暗星高于亮星**——矫正轮永不点新星
4. **无空洞感**——增删、锁定、点星、空转全部留痕日志

**独立器官**：可与帷幕沙漏同挂，也可**素跑**——不玩谜案，纯管长线文风与剧情走向。领航员用「调度员/God 连接」位。「抬头看星」按钮=紧急拉绳，任何时候手动触发一次裁决。

**盲档**：勾选后不告知哪轮点了星（星愿文本也隐藏）；故事完结后点「🌠 复盘星图」解封全账——"原来那天下雨，是我自己许的愿。"
